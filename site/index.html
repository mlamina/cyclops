On the bench

It sits next to you. You talk to it.

Assistants live in phones, tablets and apps, all built for sitting down. Cyclops is a Raspberry Pi with a camera, a speaker and a 7" screen, and it lives where the work is. No app, no account, no prompt to write. You switch it on and say what you're working on.

The real panel, mid-session: a Pico and an LCD on the bench, what the camera sees in the middle, the eye's steel cover closed bottom left.

What it does

Talk, show, and it answers in kind.

A low-latency speech-to-speech loop with a camera and a screen. You say it, it says it back, and when a picture says it better it puts one on the panel.

> talk

Just talk

No wake word and no push-to-talk. Interrupt it mid-sentence and it stops, the way a person would.

"What torque for an M6 into aluminium?"
> show

Show it what you're holding

Press the shutter and the photo goes straight into the conversation. It never takes a picture on its own.

"Which pin is ground on this?"
> draw

It draws on the screen

Wiring diagrams, a sketch of the shelf, your photo redrawn with the change. And a scratchpad for the number you need to read, not hear.

"Draw how this relay goes on GPIO 17."
> projects

Every project, kept

Each session gets filed into a project folder afterwards: a README, a log, the photos, the numbers. Next week it picks up where you left off.

> sessions

Every session, recorded

A transcript, a stereo recording with you on one side and it on the other, the photos and a screen video. It survives a power cut.

> devices

It works the hardware too

Plug a Raspberry Pi Pico into it and Cyclops can program it, run it and read it back while you hold the breadboard.

Core values

The tiebreakers.

When two designs are both reasonable, the one that keeps these wins.

  1. Hands stay free.Voice in; voice and the screen out. If it needs a keyboard, a phone or a menu, it's wrong.
  2. It never becomes the task.No settings to tend, no attention of its own. The moment you are working on Cyclops instead of the project, it has failed.
  3. Nothing gets lost.Every session is written down. What was decided, measured and left open is there next week.
  4. Good company.It has a face and a character. More fun to work with than to work without.
  5. It does what you expect.Talking to it works the way talking works. Nothing to learn, nothing to be shown.

Under the hood

One WebSocket, one loop.

  • OpenAI Realtime API for speech to speech, with server-side voice detection.
  • Barge-in: start talking and playback is cut to what you actually heard, so it knows where you stopped listening.
  • The shutter shrinks a frame to 1024 px and hands it to the model, so the next answer is about what it just saw.
  • Python, on the Pi. Nothing leaves the box except the audio and vision sent to OpenAI.

Pi setup guide 
# on the Pi
sudo apt install -y libportaudio2
curl -LsSf https://astral.sh/uv/install.sh | sh

git clone https://github.com/mlamina/cyclops
cd cyclops
cp .env.example .env   # add OPENAI_API_KEY
uv sync

# camera + API check, no audio needed
uv run cyclops-smoke

# then start the panel
uv run cyclops-kiosk
